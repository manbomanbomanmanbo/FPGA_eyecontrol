# 时钟、复位、CDC 与时序收敛

## 时钟与复位架构

列出每个时钟的来源、频率、关系、使用模块及启停条件。外部晶振、PLL／MMCM、分频、恢复时钟和转发时钟按真实结构识别，不把所有域默认视为同源同步或全部异步。

复位方式由器件、IP 和系统行为决定，不强制全同步或全异步。异步复位常采用各域异步置位、同步释放的结构；仍应检查 recovery／removal、同步级和时钟未运行时的行为。PLL lock、外部按键和电源状态信号需要按域处理。还要定义事务中复位时丢弃、排空或重启的语义。

## 根据数据语义选择跨域方法

| 跨域对象 | 常见方法 | 需检查的限制 |
| --- | --- | --- |
| 单 bit、保持足够久的电平 | 目标域同步器 | 级数与可靠性目标、最短保持时间；可能遗漏窄脉冲 |
| 单次事件或脉冲 | 拉宽、toggle 或握手 | 最短事件间隔、事件是否会合并、复位初态 |
| 多 bit 配置／快照 | 稳定数据加握手、shadow register 等 | 保持窗口、原子性和接收确认；逐 bit 同步通常不能保证一致 |
| 连续数据流 | 异步 FIFO 或适用的厂商 CDC IP | Gray 指针、同步、复位、满空、溢出和实现约束 |

同步级数没有普遍通用的固定答案，应结合目标器件、频率、事件率、布局和 MTBF 要求。优先使用经过验证的 CDC 结构及厂商识别属性，并核查 CDC／RDC 报告。给逻辑加同步器名称或属性不自动证明结构正确。

## 建立约束，而非凑齐文件

根据工具使用 XDC／SDC 或厂商等效语法；命令选项及对象集合必须由实际工程验证。

- 定义主时钟与必要的派生时钟，并核查工具自动推导结果及波形／相位关系。
- 对同步外部接口，按外设数据手册、板级延迟与时钟拓扑定义 input／output delay 的 min／max；不能只填目标周期。源同步、DDR 或高速接口需按实际采样窗口与 IP 方法处理。
- 引脚和 I/O 电平来自目标板原理图及器件 bank 条件，不生成猜测管脚。外部电压不匹配应先解决硬件接口条件。
- 核对不确定度、时钟组、例外、未约束路径、无时钟寄存器、跨时钟交互及约束对象是否真的匹配。
- 异步时钟组或 false path 会取消相应 STA 检查，但不能代替 CDC 电路；某些 CDC 实现仍需 max delay、bus skew 或专用约束。避免宽泛例外覆盖这些检查。
- multicycle 只用于逻辑确实跨多拍且接收行为满足该语义的路径，同时核查 hold 配套关系；不能看到路径超时就改成多周期。

## 从报告到修复

先核实报告对应当前目标器件、速度等级、约束和实现阶段。综合时序是估计，布局布线后结果更接近实际；不同阶段不能混称同一验证。

查看相关场景的 setup、hold、recovery／removal、脉宽和 I/O 检查；WNS 非负不足以证明所有约束完整。先确认路径是否真实、时钟关系和例外是否正确，再处理关键路径。

| 路径特征 | 优先考虑的改动 |
| --- | --- |
| 算术或优先级逻辑过深 | 切流水、平衡树、优化算法、适配 DSP／专用资源 |
| 组合 ready／控制链过长 | 注册控制、增加正确的弹性缓冲，核查吞吐和死锁 |
| 高扇出控制信号 | 降低共享扇出、局部控制或适用的复制／缓冲 |
| 布线占比高、拥塞 | 数据局部化、资源分布、减少跨区域宽总线；必要时才做布局约束 |
| 资源不足或并行度过高 | 调度复用、数据重用、重新核定精度／存储组织 |
| hold 或复位检查失败 | 核查时钟／I/O min 约束及复位结构，使用工具支持的修复方式 |

流水线改动同时更新 valid、标签、边界标记、握手与参考延迟，重新做功能检查。不要用 RTL `#delay` 修复硬件 hold。不要不经需求允许便降低目标频率，或通过例外隐藏失败。

完成后报告实际通过的时钟与时序场景、关键余量、资源、剩余警告及未约束项目。功耗估算说明激励／切换率、工作模式、温度和电源假设；缺活动数据的工具估计不等于板上功耗实测。
