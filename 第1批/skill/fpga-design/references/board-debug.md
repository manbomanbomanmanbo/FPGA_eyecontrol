# 上板与问题定位

以最少变量建立可观察链路，再逐步接入模块。流程随硬件和当前故障缩放，不要求每次重复完整硬件检查。

## 上板前确认

- 目标器件、封装、板卡、位流格式与下载方式匹配；引脚、bank 电平和外设接口由原理图或官方设计验证。
- 时钟、复位、IP 配置、初始化数据和配套软件／地址映射一致；SoC 或总线系统才需要检查处理器驱动和寄存器访问。
- 构建结果、约束、实现 DRC 及相关时序检查已经查看；对尚未通过的项目说明影响。
- 用户请求是否已包含下载或实际执行设备操作。没有连接设备时继续完成设计与离线验证，不假设上板成功；下载会影响正在运行的系统时按任务现有授权处理。

## 分阶段引入变量

1. **基础存活**：确认电源和配置状态、时钟运行、复位释放；可用简单计数／心跳或可读状态观察，LED 闪烁只证明对应小链路。
2. **控制通路**：在适用系统上核对可读身份／状态、寄存器写回、错误与清除语义；简单纯硬件模块不必专门引入 CPU 或总线。
3. **局部数据通路**：使用已知测试序列、片上发生器或环回，以计数器／校验／自检结果验证小模块。
4. **真实外设与集成**：逐项接入采集、存储、通信或执行器，观察每个边界的有效数据和错误，不一次性引入所有外设。
5. **压力与恢复**：覆盖峰值输入、输出阻塞、缓冲临界、复位、断连和重新启动；时长与环境条件由应用可靠性需求决定。

## 观察手段与故障假设

优先选择最能区分原因的观测点：状态寄存器、事务计数、FIFO 水位、溢出标志、序号、时间戳、片上逻辑分析器、外部逻辑分析仪或示波器。厂商 ILA／SignalTap 等工具按实际平台选择。

| 现象 | 先区分的原因与实验 |
| --- | --- |
| 完全无响应 | 配置、电源、时钟、复位、引脚或总线；从最小心跳／读状态开始 |
| 仿真正常、上板间歇错误 | 约束、CDC／RDC、I/O 采样、未初始化状态；捕获失败前后的握手及状态 |
| 少量数据正确、大流量失败 | 持续带宽、突发、反压和溢出；测边界计数与水位 |
| 数据整体错位或周期性错位 | 延迟对齐、帧边界、端序、位宽、跨域和丢样；用带序号的输入定位首个分歧 |
| 提高频率后出错 | 实现时序、外设时序、时钟质量或供电；核对对应路径和接口条件 |
| 控制命令返回但外设无动作 | 命令接受、实际发送、电气接收和执行完成分别观察 |

对每个怀疑点选择能证伪的实验，记录输入、观测与结论。不要无依据地重复烧录、增加任意延时或把参数调到“看起来正常”。

调试核、探针和额外计数器会改变资源、扇出、布局及可能的时序，插入后重新实现并核查；撤掉后如需声明正式构建通过，也要核对对应结果。

## 测量设计指标

- 明确端点：输入引脚、内部握手、输出引脚、主机 API 和外设完成信号测得的是不同延迟。
- 吞吐统计实际接受／完成的事务和真实时间，区分 payload 与线路速率、平均与峰值；丢包或重复结果不能算有效吞吐。
- 延迟记录时钟／时间基准、输入负载、反压和排队条件。跨域时间戳需定义同步／换算方法；未同步的时间不能直接相减。
- 与软件或旧方案比较时使用相同算法、精度、数据和端到端边界；区分内核运算加速与系统加速。
- 结果说明样本数、持续时间、设备与测试条件。温度、电源和环境适应性结论只覆盖实际测试范围。

最终将已定位根因、已完成修复、复测结果与待验证猜测区分开。没有仪器或实物时给出可执行的信号观测和判定方法，不用方案推演代替测量记录。
