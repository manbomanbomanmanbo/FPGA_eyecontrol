# 需求、选型与架构

## 用预算排除不可行方案

先定义测量边界与单位，再计算。区分有效载荷和链路开销、平均值和突发峰值、理论峰值和持续可用值。

- 数据率：每秒样本／像素／事务数乘以实际存储或传输位数；图像应核对分辨率、帧率、通道数和打包方式。
- 流水线：稳定阶段吞吐约为 `f_clk / II` 个输出每秒；需满足输入有效及输出可接收。`II` 为启动间隔，不能用级数替代。
- 延迟：固定 L 周期时处理延迟为 `L / f_clk`；端到端还包括排队、缓存、跨域、传输与外设延迟。反压或仲裁可能使延迟可变。
- 存储：按行／帧／窗口／队列深度和位宽计算容量，同时检查 RAM 的端口、读延迟、宽深组织与冲突，不能只看总 bit 数。
- 缓冲：用累计输入减累计输出的最大积压估算所需深度。长期输入率高于输出率时，有限 FIFO 无法解决；没有明确突发和阻塞上限时不能保证永不溢出。
- 外存：统计每个输出的全部读写量，包括中间结果和重复访问；理论接口带宽还受突发长度、刷新、行切换、仲裁与访问模式影响。
- 计算：按每样本运算数、并行单元、调度与可用周期估算资源和吞吐。乘法器数量不等于 DSP 数量，映射受位宽、器件结构及综合推断影响。

计算结果应能复算；关键假设不确定时给出区间或情景。不要凭任意“效率百分比”宣称 DDR 带宽或资源足够。

## 平台与实现路线

已选板卡时尊重硬件条件，先评估是否能完成目标。需要选型时比较的变量包括：逻辑和寄存器、DSP 类型、片上存储、PLL／时钟资源、外存控制器、收发器、I/O bank 与电平、封装、速度等级、工具／IP 许可、功耗、价格与供货。

不以资源最多为最优；封装引脚、I/O 电平、外设接口或工具支持可能先构成限制。对具体器件的硬核支持和性能上限必须查目标系列资料；同一厂商不同系列也不能互相套用。

根据瓶颈选择：

| 情况 | 优先考虑 | 需要核查 |
| --- | --- | --- |
| 周期预算宽松 | 迭代／时分复用 | 调度、状态保存和最坏延迟 |
| 连续流且计算链长 | 流水线 | 级间有效信号、反压、反馈依赖 |
| 单通道流水吞吐不足 | 多路并行 | 输入分发、存储带宽、结果重排 |
| 邻域／滑窗运算 | 行缓冲和数据重用 | 边界、读写端口、行帧有效信号 |
| 数据相关或控制密集 | FSM、微码或软硬件协作 | 最坏执行路径、软件调度和搬运成本 |

系统中存在 CPU、MCU 或主机时，再按确定性、吞吐、资源及开发成本划分任务。FPGA 可只承担关键链路，不要求把配置、UI 或复杂控制全部硬件化。

已有或计划使用 HLS 时，同样先定义吞吐、延迟、数值格式和接口。检查循环依赖、存储端口、流水调度及数据流阻塞；unroll／pipeline 指令不保证达到目标 II。将 C／C++ 功能仿真、综合调度报告、C／RTL 协同仿真及布局布线结果分别验证，不把 HLS 的频率／资源估计作为最终实现结果。

## 数值设计

先用可检查的参考模型描述算法，再决定整数、定点或浮点。定义符号、单位、位宽、二进制小数位、量程、舍入、饱和或回绕及误差标准。

- 若原值表示为整数 `X` 和 `Y`，实际量分别为 `X·2^-Fx`、`Y·2^-Fy`，乘积的初始小数位数为 `Fx+Fy`；缩位时显式处理舍入和溢出。
- 保守全精度无符号加法需要 `max(Wa,Wb)+1` 位；乘法通常保留 `Wa+Wb` 位。具体 HDL 表达式仍必须显式扩展和检查符号，不能依靠左侧宽度修复所有中间截断。
- N 项累加可从最大项宽度外加 `ceil(log2(N))` 个保护位作保守起点，再按真实数值范围分析；相关性、系数符号和特殊输入可能影响界限。
- 除法、开方和三角函数按精度、吞吐与延迟比较迭代、查表、分段近似、CORDIC 或厂商 IP；声明有效输入域和误差，不盲目替换。

浮点模型用于算法检查，位精确模型用于量化行为检查。验证最小／最大、零、符号翻转、阈值附近、舍入边界与溢出；随机误差小不能替代边界证明。

## 架构完成时应明确

说明数据从哪里进入、如何缓存和计算、结果如何输出；每个模块的时钟域、接口、位宽、状态和预计延迟；关键带宽／资源预算；最大的未验证风险。只有涉及复杂权衡时才并列多个方案，不堆砌没有计算依据的选项。
