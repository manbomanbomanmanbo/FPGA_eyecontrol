# RTL 与功能验证

## 从契约开始

实现前明确：时钟边沿、复位极性和时序、数据格式、采样／提交时刻、延迟、能否连续接受输入、阻塞处理和异常行为。用周期表或少量示例消除歧义，再写 RTL。

按用户工程选择 Verilog、SystemVerilog 或 VHDL 及可用语言特性。组合逻辑完整赋值，时序逻辑使用对应的寄存器赋值语义，单一状态避免多驱动；FSM 明确输出和状态转移条件。不要只靠代码风格判断逻辑正确。

## 容易形成实际故障的细节

- 显式定义位宽、符号、常量尺寸、扩展、截断与算术移位；检查乘加中间结果及有符号／无符号混合比较。
- 参数化设计检查最小值、非二次幂、零宽向量和 `$clog2(1)`；不支持的参数组合应在 elaboration 或仿真早期给出清晰错误。
- 计数器、长度和索引区分“数量”与“末项编号”；检查零长度、一项、最后一拍、饱和和回绕。
- RAM／ROM 的读延迟、同址读写行为、初始化支持按目标器件和推断模板确认；不要用大范围逐项复位无意破坏存储器推断。
- 控制与数据流水保持同样的有效性和延迟。若采用全流水反压冻结，相关状态必须一致停住；若用弹性流水，逐级实现独立占用和传递。
- 优先使用时钟使能，避免普通逻辑直接门控时钟。需要时钟切换、分频或门控时按目标器件专用资源和约束处理。
- 不把仿真延时、testbench 的文件 I/O 或不支持的动态结构写入预期可综合逻辑；初始化和 ROM 文件能否上硬件以工具支持为准。

## 接口验证重点

对于常见 ready／valid 流接口，以协议定义的采样边沿上二者同时有效作为传输；一般在 valid 已置位而 ready 未就绪时保持 valid 和载荷稳定，直至接受或按协议复位。不要把这一规则无条件套给具有不同 ready latency 或时序定义的接口。

- FIFO：满／空临界、连续读写、同时读写、复位和深度边界；溢出／下溢应按约定阻止或报告。
- 总线：地址、对齐、byte enable、响应和错误。AXI 类接口各通道独立握手，不假设地址与数据总在同一拍，检查 outstanding 与响应配对。
- 采集／通信：帧／包／行边界、长度、字节序、校验和、无效间隔与重新同步。
- SPI／UART／I²C 等外设：按实际协议核对采样边沿、模式、速率容差、电气驱动方式和超时；无需为简单接口默认引入复杂总线框架。
- 跨时钟数据：功能测试覆盖不同时钟比、相位、突发与两侧复位；仿真不模拟真实亚稳态，仍需结构和约束检查。

## 让测试给出可判断结果

根据任务采用现有 testbench、HDL 自检、cocotb、脚本参考模型或适用框架。为需要新验证的行为选择最简单够用的方法；不默认引入 UVM。

1. 先编译／elaborate，再做复位、最小有效事务和典型输入。
2. 用已知答案或独立参考模型校验输出；模型不应逐句照抄 RTL，以免复制同一错误。
3. 覆盖真实风险：极值、阈值、连续／稀疏有效、随机反压、FIFO 边界、事务中复位、非法输入和重新启动。
4. 流水线使用 scoreboard 依据实际握手入队出队；可变延迟设计不能只在固定拍数比对。用标签或顺序规则验证无丢失、重复、乱序。
5. 测试必须有超时、错误计数及明确退出状态；结束前检查预期结果已全部收到。生成波形不等于测试通过。
6. 对适用不变量添加断言，例如阻塞时载荷保持、计数器范围、请求／响应关系。形式验证用于边界状态或并发协议确有价值的部分，并说明假设与证明范围。

新测试需实际运行。缺仿真器或厂商加密 IP 模型时，先利用可用工具验证可独立的部分，并准确记录未完成层级；不能将语法解析声称为仿真通过。

综合后回查：意外锁存器、组合环、多驱动、未连接端口、截断、未识别 RAM／DSP、不可达状态和资源异常。出现警告时判断其实际影响，不机械要求零警告，也不一概忽略。
